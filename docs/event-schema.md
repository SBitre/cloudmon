# Event Schema

All events sent to the ingest API must conform to this schema. This contract is shared by the simulator, the ingest Lambda, the detection Lambda, and the dashboard.

## Required fields

| Field | Type | Description | Example |
|---|---|---|---|
| `event_id` | string (UUID) | Unique ID per event, generated by sender | `"a3f8e2c1-..."` |
| `timestamp` | string (ISO 8601 UTC) | When the event occurred | `"2026-05-01T14:23:11Z"` |
| `service` | string | Which service emitted the event | `"login-service"` |
| `event_type` | string | What happened | `"failed_login"` |
| `severity` | string | One of: `info`, `warning`, `error`, `critical` | `"warning"` |

## Optional fields (depend on event_type)

| Field | Type | Used by event types |
|---|---|---|
| `user_id` | string | Login, payment events |
| `ip_address` | string | Login, API events |
| `endpoint` | string | API events |
| `status_code` | integer | API events |
| `error_message` | string | All error events |
| `metadata` | object | Free-form additional context |

## Supported event types

- `successful_login` — normal successful login
- `failed_login` — wrong password or auth failure
- `api_call` — generic API request
- `api_error` — API request that failed (4xx/5xx)
- `payment_success` — completed payment
- `payment_failed` — failed payment
- `traffic_spike` — synthetic event for testing

## DynamoDB table schema

**Table:** `cloudmon-events`
- **Partition key:** `service` (string)
- **Sort key:** `timestamp` (string, ISO 8601 — sortable as string)
- **Other attributes:** all the fields above

**Table:** `cloudmon-alerts`
- **Partition key:** `alert_id` (string, UUID)
- **Sort key:** `timestamp` (string)
- **Other attributes:** `service`, `anomaly_type`, `severity`, `explanation`, `recommended_actions`, `triggering_events`
